# NavMesh 模块设计文档

## 概述

NavMesh（导航网格）模块将网格地图抽象为**连通区域**和**多边形边界**，为上层 AI 提供地图的“语义”理解能力。

与网格 A星（在单个网格上做路径搜索）不同，NavMesh 更关注地图的结构化描述：哪些格子是连通的、它们组成什么形状、边界在哪里。

### 适用场景

-- 1. 地图**可通行区域**的自动提取与抽象

-- 2.  游戏调试可视化（显示区域边界）

-- 3. 为后续跨区域寻路提供数据基础（预留扩展）

---

## 一、核心流程

### 流程图

区域是**彼此连通的可行走格子的集合**。如果两个格子可以通过上下左右移动相互到达，它们属于同一区域。

```text
GridMap（网格地图）
        │
        ▼
┌───────────────────┐
│   RegionMarker    │  ← 并查集标记连通区域
│  MarkRegions()    │  → region_ids（每个格子所属区域 ID）
└───────────────────┘
        │
        ▼
┌───────────────────┐
│  PolygonExtractor │  ← 边界跟踪 + 多边形提取
│ ExtractPolygons() │  → regions_（多边形顶点 + 中心点）
└───────────────────┘
        │
        ▼
┌───────────────────┐
│   PortalDetector  │  ← 可扩展接口（当前未使用）
│   DetectPortals() │  → portals_（区域之间的连接点）
└───────────────────┘

```

## 二、模块详解

### 2.1 RegionMarker（区域标记）

使用并查集（Union-Find）算法将连通的格子合并为同一区域。

算法要点：

-- 1. 从左到右、从上到下扫描每个格子

-- 2. 检查左方和上方的格子是否可行走

-- 3. 如果当前格子与左方或上方连通，继承其区域 ID

-- 4. 如果左右上方属于不同区域，合并两个区域


### 2.2 PolygonExtractor（多边形提取）

将每个区域的格子集合转化为多边形轮廓。

提取步骤：

-- 1.  收集每个区域的边界格子

-- 2.  将边界格子的角点排序形成多边形

-- 3.  简化多边形（去除共线点）

-- 4.  计算多边形质心（面积加权平均）

### 2.3 多边形质心计算

采用面积加权平均（比顶点平均更精确）：

```cpp
void CalculateCentroid() {
    // 以顶点 0 为基准，将多边形剖分为三角形
    for (size_t i = 1; i < n - 1; ++i) {
        // 计算三角形面积（叉积的一半）
        float area = (p1 - p0) × (p2 - p0);
        // 三角形重心 = 顶点平均
        float tri_cx = (p0.x + p1.x + p2.x) / 3.0f;
        // 加权累加
        cx_sum += area * tri_cx;
        area_sum += area;
    }
    center_x = cx_sum / area_sum;
    center_y = cy_sum / area_sum;
}

```

## 三、设计取舍

|算法	| 用途	| 复杂度|
|-------|--------|--------|
|并查集区域标记|	标记连通区域	|O(n)|
|射线法	|判断点是否在多边形内	|O(k)|
|鞋带公式	|计算多边形面积	|O(k)|
|面积加权平均	|计算多边形质心	|O(k)|
|边界跟踪	|提取多边形轮廓	|O(n)|


|选择  |	理由|
|-------|--------|
|基于连通性划分区域 |	区域的定义天然是“连通的可行走集合”|
|一维数组存储网格	| 内存连续，CPU 缓存友好|
|多边形提取简化|	使用边界跟踪 + 共线点移除，满足可视化需求|
|PortalDetector 暂缓使用	| 当前地图整体连通，网格 A* 已足够|
|保留扩展接口|	预留跨区域寻路的可能性|
